## 2024-06-27 - Global Event Listeners and Unconditional DOM Queries Anti-Pattern
**Learning:** I discovered a codebase-specific anti-pattern where global event listeners (like the document 'click' and 'toggle' handlers in `script.js`) unconditionally execute DOM queries (`querySelector` and `querySelectorAll`) or properties update on every event trigger, even when it's not necessary (e.g. closing a dropdown that's already closed, or closing a details element that's already closed). This is particularly impactful for common events like 'click' which fire often, blocking the main thread pointlessly. Furthermore, querying static node lists inside event callbacks rather than caching them globally causes redundant processing.
**Action:** When adding global event listeners or dealing with frequently fired events, always cache static element lists at the top level to avoid re-querying. For event callbacks that manage UI state, always add guard conditions (like checking `classList.contains('open')` or if an element's state is truly active) before performing DOM lookups or attribute updates.
